# עין צופיה

אפליקציית Full Stack לניהול תמונת מצב של התראות מודיעיניות - הצגה על מפה, רשימה, הוספה, עדכון, מחיקה, חיפוש וסינון.

## מבנה הפרויקט

- `server/` - Node.js + Express + MongoDB
- `client/` - React + TypeScript + Vite

## למה MongoDB

הנתונים (התראות) הם במבנה קבוע ואין צורך בקשרים בין אחד לשני על ידי טבלאות ו MongoDB מתאים בדיוק לזה.

## Status Codes


| קוד | מתי                                                    | למה                                               |
| -------- | ----------------------------------------------------------- | ------------------------------------------------------ |
| 200    | GET/PUT/DELETE שהצליחו                             | בקשה תקינה שלא יצרה משאב חדש  |
| 201    | POST שיצר התראה חדשה                         | משאב חדש נוצר בהצלחה                |
| 400    | קלט לא תקין (שדה חסר/ערך לא חוקי) | שגיאת לקוח - הבקשה עצמה פגומה |
| 404    | התראה לא נמצאה לפי id                      | המשאב המבוקש לא קיים                |
| 500    | שגיאה לא צפויה בשרת                       | כל מה שלא טופל במפורש               |

## ולידציה

כל יצירה/עדכון של התראה עוברת דרך middleware ייעודי (`server/middleware/validatations.js`):

- **יצירה** - כל השדות חובה: `displayName`, `description`, `priority`, `arena`, `status`, `lon`, `lat`.
- **עדכון** - כל השדות אופציונליים (עדכון חלקי/דינמי), אבל אם שדה נשלח - הוא נבדק באותם כללים.
- **ערכים מוגבלים**- `priority` חייב להיות אחד מ-`Low/Medium/High/Critical`, `arena` מ-`North/South/Center`, `status` מ-`Active/Handled`.
- **`lon`/`lat`** - חייבים להיות ניתנים להמרה למספר.
- **שדות לא מוכרים** - נדחים (כדי שטעות כתיב בשם שדה לא תיכנס בשקט כשדה חדש במסמך).

כשהקלט לא תקין, השרת מחזיר `400` עם הודעת שגיאה בעברית לכל שדה בעייתי.

## State בצד הקליינט

ניהול ה-state המרכזי (רשימת ההתראות וכל הפעולות עליה - fetch/create/delete/update) נעשה עם **zustand** (`client/src/store/alertsStore.ts`) - store גלובלי אחד שעוטף את קריאות ה-API.

**חיפוש וסינון** (לפי שם/זירה/סיווג) לא נמצאים ב-store הגלובלי, אלא כ-`useState` מקומי בכל דף (`HomePage`, `AlertsListPage`) + `useMemo` לחישוב הרשימה המסוננת. הסיבה: כדי שהפילטרים יתאפסו אוטומטית במעבר בין דפים וברענון.
